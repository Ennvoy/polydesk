# 103 WSL 清理限制改寫入完整使用說明，不強制跳窗

- 背景：決議 098 決定在 WSL 分頁的關閉確認視窗上載明「WSL 內部的程序無法清理」。獨立審查指出該揭露永遠不會顯示——WSL 分頁的 console 清單僅含 `wsl.exe` 本身，扣除後即為「零殘留」，依決議 092「沒有存活子孫時照舊一點就關、不跳視窗」，該視窗根本不會出現。若為此讓 WSL 分頁無條件跳窗，又會破壞「無殘留不打擾」的原則。
- 決定：**改寫入程式內的完整使用說明**——載明「WSL 分頁內啟動的程式屬 Linux 端程序，Polydesk 無法列出或清理，需自行於 WSL 中處理」。不因 WSL 而強制跳出關閉確認視窗；092 的「無殘留不跳窗」原則維持不變。
- 原因：一個內容固定、每次都相同的強制彈窗，很快就會被使用者無視按掉，實質揭露效果反而低於一份查得到的說明；而為了少數情境讓日常操作多一次點擊，不符合使用者一貫的極簡偏好。代價是使用者需主動查閱說明才會知道此限制。
- 證據：使用者於彈窗選擇「寫進使用說明就好（推薦）」。當時依據為決議 092 的無殘留不跳窗規則，與 `PtyManager.ts:30` `VALID_SHELLS` 含 `'wsl'` 的讀碼確認。
- 修訂：本決議修正 098 的揭露位置（由關閉確認視窗改為完整使用說明），揭露內容與「不假裝已清理」的立場不變。
