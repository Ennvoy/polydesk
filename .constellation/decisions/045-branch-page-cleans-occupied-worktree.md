# 045 分支頁完整清理被佔用分支

## 背景

現行分支頁對任一 worktree 正在使用的本地分支停用刪除，使用者必須先切到 worktree 分頁移除工作區，再回到分支頁刪除分支。

## 決定

分支頁刪除一條正被 worktree 使用的本地分支時，不再停用操作，而是直接開啟完整清理流程。若該分支因外部強制操作同時被多個 worktree 簽出，確認畫面必須逐一列出全部路徑、納管／失效／lock、未提交變更與未合併 commit 風險；通過對應防護後，依序關閉全部受影響工作區資源、移除所有 linked worktree，最後才刪本地分支。

## 原因

一站式流程才能真正達成「從 Polydesk 刪除分支就完全清乾淨」，同時沿用已有的 dirty 確認、teardown 與二階段強制刪除保護，不降低資料安全。

## 證據

訪談題目：「如果在分支頁刪除一條正被其他 worktree 使用的分支，Polydesk 要怎麼處理？」使用者選擇選項 1：「直接開啟完整清理流程（推薦）」。當時依據為現行分支頁已能由 `git worktree list` 精確得知佔用路徑，而 worktree 移除已有終端機與檔案 handle 釋放流程可重用。
