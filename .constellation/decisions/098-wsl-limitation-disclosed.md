# 098 WSL 分頁誠實揭露清理能力限制

- 背景：`PtyManager.ts:30` 的 `VALID_SHELLS` 含 `'wsl'`。WSL 分頁內啟動的程序為 Linux 側程序，Windows 端僅可見 `wsl.exe` 與 `vmmem`，ConPTY console process list 與 `taskkill` 皆無法列舉或終止。因此「清得從底」對 WSL 分頁本質上失效，且使用者無從由畫面分辨。
- 決定：WSL 分頁仍照常走關閉確認流程，但視窗上明確載明「WSL 內部的程序無法清理，請自行於 WSL 中處理」。不假裝已清理完成，也不因此停用 WSL 分頁的關閉確認。
- 原因：專案既有原則為失敗不得偽裝成功（`MAP.md` 已知地雷段、決議 077 等一貫立場）。若不揭露，使用者會取得假的綠燈；若直接停用該分頁的確認，兩種分頁行為不一致且畫面上看不出原因，反而更難理解。
- 證據：使用者於彈窗選擇「老實在畫面上講明（推薦）」。當時依據為 `VALID_SHELLS` 讀碼確認，以及決議 095 實測確立的 console list 機制僅涵蓋 Win32 程序。
