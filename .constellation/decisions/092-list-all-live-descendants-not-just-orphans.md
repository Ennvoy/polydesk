# 092 關閉確認清單涵蓋該分頁全部存活子孫，不只孤兒

- 背景：改為「清得從底」後若只詢問孤兒程序，同一個 dev server 會因為「起它的 AI 有沒有退出」而有不同待遇——parent 鏈完整者依現況直接終止不詢問，已孤兒化者才列出詢問。使用者無法從畫面分辨兩者差異。
- 決定：關閉確認清單列出該分頁底下**全部仍存活的子孫程序**，不分由使用者手動啟動或 AI 啟動、不分 parent 鏈是否完整。分頁底下沒有任何存活子孫時，照舊一點就關、不跳視窗。
- 原因：以「這個分頁底下還有東西在跑就問你」作為單一規則，行為可預測且一句話說得完；只問孤兒則會產生使用者無從預期、也無從觀察的差別待遇。代價是使用者本就打算連同 dev server 一起關閉時會多一次確認，但該情境下的確認並非冗餘——它正是使用者要求的「不要不知不覺殺掉東西」。
- 證據：使用者於彈窗選擇「全部都列，不分誰起的（推薦）」，題目說明了「同一台 dev server，兩種命運」的落差。當時依據為決議 088 已確立的詢問原則與本機孤兒存活實測。

> **修訂（095）**：「全部存活子孫」重新定義為「ConPTY console 清單成員」；原意（不分誰啟動、一律列出）不變。
