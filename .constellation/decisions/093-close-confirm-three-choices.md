# 093 關閉確認提供三個選擇，保留「只關分頁」

- 背景：關閉分頁偵測到存活子孫時會跳出確認（決議 088、092）。「取消」在此情境有歧義——可能指不關分頁，也可能指關分頁但保留那些程序，而後者正是現行行為。
- 決定：確認視窗提供三個選擇——「一併關閉」（分頁與全部存活子孫一起收掉）、「只關分頁」（收掉分頁、程序繼續執行，等同現行行為）、「取消」（不執行任何動作）。關閉工作區的合併確認沿用同一組語意。
- 原因：使用者可能想收掉分頁但保留 dev server 繼續看畫面，這是今天已經做得到的事；若只給「一併關閉／取消」，等於為了保留一個服務而被迫留著整個分頁，是能力倒退。代價是選「只關分頁」會親手製造一批之後認不出來的孤兒（分頁消失、帳本一併註銷），此代價由使用者當下自行承擔。
- 證據：使用者於彈窗選擇「三個：一併關閉／只關分頁／取消（推薦）」。當時依據為現行 `PtyManager.close` 對孤兒無作用的實測結果——「只關分頁」即為現況行為的顯式化。
