# 108 名稱改以 tasklist 於關閉當下即時查詢，取代背景快取

- 背景：決議 105 將名稱查詢移出關閉流程、改由背景快取供應，論證基礎是「成本大頭在啟動查詢程序本身（單次 PowerShell 啟動即 1,285–1,974 ms）」。該量測僅涵蓋 PowerShell，未涵蓋 Windows 原生的 `tasklist`。
- 決定：**名稱改於關閉當下以 `tasklist` 即時查詢**，不再維護背景名稱快取、亦不需為此將 `aiProcessScan` 改為全列舉。關閉流程總延遲約 0.7 秒（console 清單約 200 ms ＋ tasklist 全列舉約 500 ms），清單內容為當下真實狀態。
- 原因：本機實測顯示 `tasklist` 列出全機 349 個程序僅需 524–549 ms、查單一 PID 僅 197–222 ms，與 PowerShell 的 816–1,015 ms（單一 PID）差距四至五倍——105 的成本前提只對 PowerShell 成立。改為即時查詢後同時消除三項衍生問題：無需維護背景名稱快取、無需改動既有 AI 掃描（連帶消除「有 wmic 的機器新增每 8 秒全列舉負擔」的疑慮）、名稱不會過期。後者尤其重要——決議 088 的立論是使用者依清單內容做不可逆決定，而陳舊名稱正是誤導的來源。
- 證據：本機量測——`tasklist` 單一 PID：209／222／197 ms；`tasklist` 全列舉（349 行）：549／524／532 ms；PowerShell 單一 PID：1,015／816 ms。另量得 console process list 查詢 213／210／208／199 ms，平行查 3 次僅 204 ms（平行幾乎不增加耗時）。
- 取代：本決議取代 105 的名稱供應方式與「aiProcessScan 改全列舉」的要求；105 的核心分工（殺誰＝即時查 console 清單）不變。決議 106 的入口 PID 仍需背景記錄，其實作方式改由開工時依實測選擇，不再綁定 aiProcessScan 全列舉。
