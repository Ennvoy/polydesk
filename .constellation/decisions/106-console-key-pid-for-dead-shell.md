# 106 以「入口 PID」查詢已結束終端機的殘留，修正決議 102 的不可行時序

- 背景：決議 102 要求在終端機結束當下（`onExit`）搶查一次 console process list。獨立審查指出該時序不成立，本機實測證實——`AttachConsole` 要求目標程序當下存活，而 `onExit` 被觸發的前提正是 shell 已結束。實測：shell 存活時查詢成功回傳 `[24212,20276,17504]`；`onExit` 當下查詢於 117 ms 內失敗（`Error: AttachConsole failed`）。**這不是偶發失敗而是結構性失敗，102 原做法每次都會失敗。**
- 決定：改以**入口 PID** 查詢。背景掃描（決議 105 已要求改為全列舉）順手記下每個 pty shell 底下任一個子程序的 PID 當作入口；shell 自行結束後，改用該入口 PID 執行 `AttachConsole` 查詢，即可取得該 console 的完整成員清單並據以清理。查詢代理自身的 PID 必然出現在回傳清單中，須排除。
- 原因：本機實測證實 shell 結束後仍可用同一 console 的其他存活成員成功查詢——以孤兒自身 PID（17652）attach 成功，回傳 `[27364,17652]`；而以已結束的成員 PID（4912）則失敗。此做法與使用者先前否決的背景帳本有本質差異：帳本是拿數秒前的快照直接作為終止依據（會漏列、會因 PID 重用誤殺），入口 PID 僅作為查詢入口，**實際清單仍為關閉當下即時查得**，準確度不受掃描間隔影響。成本為零，搭既有掃描順風車。已知限制：若掃描窗口內該終端機底下完全沒有任何程序被記錄到，該次仍會漏失。
- 證據：使用者於彈窗選擇「照修正版做（推薦）」。實測數據見上（`test-onexit-attach.js`、`test-host-attach.js`）。另證實 ConPTY 宿主程序不出現在 `GetConsoleProcessList` 回傳中，故「建立時記下宿主 PID」的替代路徑不可行。
- 取代：本決議取代 102 的查詢時機與入口，102 的目的（補上 shell 自行結束時的失聯點）不變。
