# 091 殘留程序帳本只存記憶體，不跨 Polydesk 重啟

- 背景：殘留清理涵蓋關閉分頁、關閉工作區與關閉 Polydesk 三條路徑（決議 089），辨識依據為背景維護的程序帳本（決議 090）。若 Polydesk 遭強制結束（當機、工作管理員終止、開發時直接砍除），「關閉時安靜清理」無機會執行，記憶體中的帳本亦一併消失，該次殘留將無法再被辨識。
- 決定：帳本只存於記憶體，**不落磁碟、不跨重啟**。強制結束造成的殘留不予處理，使用者需自行以工作管理員清除。
- 原因：三條正常關閉路徑已覆蓋絕大多數情境，僅異常結束會漏。落磁碟需新增存檔格式、版本遷移，並額外處理 PID 重用（須以程序建立時間交叉比對，否則跨重啟後可能終止無關程序），工程量與風險明顯上升；且啟動時跳出「上次有殘留」的視窗會打擾正常使用。維持範圍最小化。
- 證據：使用者於彈窗選擇「不處理，接受這個洞（推薦）」，題目為「Polydesk 被強制結束時……下次開 Polydesk 就認不出那些殘屍了，只能你自己開工作管理員找。要不要處理這個情況？」。當時依據為決議 089／090 既有設計，無外部量測資料。

> **superseded by 095**：背景帳本設計已廢除，改用 ConPTY console process list 即時查詢。
