# 050 完整清理的單一確認狀態機

## 背景

既有一般分支確認、未合併二階段確認、遠端額外確認與完整風險摘要若各自實作，會產生重複或互相矛盾的對話框。

## 決定

所有本地分支共用單一「刪除／完整清理」入口，第一階段一律可選擇本機範圍、目前分支的切換目標，以及是否連同清理遠端。普通分支若未選遠端，經基本確認後真實嘗試安全刪除；成功即結束，Git 拒絕時才開第二階段風險摘要。選了遠端、目前分支或 worktree 使用中分支，則在無副作用預檢後以一個風險摘要作為最後第二階段。

## 原因

這個狀態機讓已合併的日常清理維持兩步，又讓會刪除工作目錄、未合併 commit 或遠端的情境在真正變更前只看一份完整摘要。遠端勾選會在最後摘要內以獨立核取再次確認，不與 dirty 或強制刪除共用一個授權。

## 證據

使用者授權「全部依照你的建議做完」。獨立盲點審查指出決議 004、043、047、049 尚未定義彼此取代與衔接關係，因此採用上述推薦單一狀態機。
