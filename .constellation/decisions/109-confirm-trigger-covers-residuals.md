# 109 關閉確認的觸發條件改為「有存活終端機或有殘留程序」

- 背景：現行關閉確認的觸發條件為「該工作區有 alive 終端機」（`src/main/index.ts:214` 的 `hasRunningProcesses`，實作見 `PtyManager.ts:507`；`CloseConfirm.tsx:48/53` 於 `alive.length === 0` 時直接放行不跳窗）。獨立審查指出該條件與本輪要清理的對象不一致——終端機已全數結束但底下仍有殘留程序時，條件為 false、視窗不出現，退出時直接靜默終止。
- 決定：三條關閉路徑的確認觸發條件一律改為「**有存活終端機 或 有殘留程序**」，任一成立即顯示確認。兩者皆無時維持一點就關、不跳窗（決議 092 原則不變）。
- 原因：終端機已關閉但 dev server 仍在執行，正是 AI 跑完自行退出後最常見的狀態，也是本輪功能的核心目標情境；照現行條件，這個情境會完全繞過決議 088 建立的保護（「終止使用者可能仍在使用的 dev server 屬不可逆行為，事後告知無法挽回」），使該保護在最需要它的時候失效。代價為「終端機都關完才關 Polydesk」的情境下，若底下仍有殘留會多跳一次確認——但那正是應該詢問的時刻。
- 證據：使用者於彈窗選擇「改成『有終端機或有殘留』就跳（推薦）」。當時依據為 `index.ts:212-216`、`PtyManager.ts:507-510`、`CloseConfirm.tsx:44-53` 之讀碼確認。
