# 102 終端機結束當下搶查一次殘留清單

- 背景：決議 095 以 ConPTY console process list 辨識殘留，該查詢需 `AttachConsole(shellPid)`，shell 結束後即無從查起。獨立審查指出，使用者輸入 `exit`、shell 崩潰、或使用「重啟」時，該分頁任內的殘留即永久失聯——之後關閉分頁、移除工作區或關閉 Polydesk 都清不到。決議 091 當時取得的同意是針對「Polydesk 被強制結束」，而 shell 自行結束的頻率遠高於此，屬拍板時未揭露的能力損失。
- 決定：在偵測到終端機結束的當下（`PtyManager.onExit`）**立即搶查一次** console process list 並保存結果，供後續關閉路徑清理使用。查得到就納入清理範圍，查不到則維持現況、不阻塞任何流程。
- 原因：此做法成本極低——只在終端機結束的那一次執行，而非背景持續輪詢；相對地「背景持續記錄」等同復活已於 095 廢除的帳本設計，且需為每個終端機每輪掃描額外 fork 一次查詢程序，使用者有多個工作區時負擔明顯。已知限制為不保證每次都搶得到：shell 結束過快或崩潰時 console 可能已拆除，該次仍會漏失，此限制須誠實揭露、不得宣稱已完全解決。
- 證據：使用者於彈窗選擇「終端機一死就馬上搶查一次（推薦）」，題目已明確載明「不保證每次都搶得到」。當時依據為 `node_modules/node-pty/src/win/conpty_console_list.cc` 的 `FreeConsole`／`AttachConsole` 實作（目標程序不存在即 throw），以及 `PtyManager.ts:594-605` 既有的 `onExit` 掛載點。
- 補充：091「帳本只存記憶體、不跨重啟」的結論不變；本決議只補上「shell 結束」這個中途失聯點，不改變跨 Polydesk 重啟的行為。
