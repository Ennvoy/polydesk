# 043 本地分支二階段強制刪除

> clarified by 050、051：普通分支會真實先試安全刪除；目前或 worktree 使用中的分支先做無副作用預檢，並在同一 repository 事務內重驗。

## 背景

現行本地分支刪除固定使用 Git 安全模式，含未合併 commit 時只會阻擋；新需求要求 Polydesk 內也能完整清理，但不能把誤按直接變成無法復原的資料遺失。

## 決定

本地分支先執行安全刪除；只有 Git 判定尚未合併時，才顯示第二階段高風險確認，列出未合併 commit 數量並要求使用者明確確認後，再以強制模式刪除。

## 原因

二階段流程可以在 Polydesk 內完成清理，同時讓一般已合併分支維持低摩擦的安全刪除，只對真正可能遺失 commit 的情況增加警示。

## 證據

訪談題目：「遇到含有未合併 commit 的本地分支時，Polydesk 應該怎麼刪？」使用者選擇選項 1：「兩階段強制刪除（推薦）」。當時依據為 `profile` 分支有 6 個 Git 判定未合併的 commit，現行 `git branch -d` 必然拒絕刪除。
