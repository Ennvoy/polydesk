# 120 SCM 歷史分批載入

## 使用者決定

「那就先改成20，如果我需要往下看，滾到底的時候再每次載入10筆可以嗎」

SCM「歷史」首次顯示 20 筆；往下捲到列表底部時，每次再載入 10 筆，直到歷史末頁。保留原本可查看的完整歷史範圍，不設固定總筆數上限。分批載入是為了先呈現眼前需要的提交，讓使用者需要往下看時再取下一批。

## 程式現況與實作依據

決定前，`SourceControlPanel.tsx` 固定呼叫 `git:log({ wsId, limit: 50 })`；`GitService.log` 以 `git log --all --topo-order --decorate=full -n <limit>` 取得列表。因此現有畫面最多顯示 50 筆。v0.38 真 Electron 前圖以 60 筆真 Git 提交驗證，畫面從第 60 筆顯示到第 11 筆，捲到底仍只有 50 筆。新分頁應維持 `--all` 的本地與遠端追蹤範圍及 `--topo-order` 的線圖順序。分頁限制的是每次回傳和呈現的筆數，不據此承諾 Git 內部只走訪同樣筆數或保證載入時間。
